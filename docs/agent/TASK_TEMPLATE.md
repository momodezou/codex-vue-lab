# AI 开发任务模板

复制后按任务填写。适用于新功能、缺陷修复和代码重构。共通开发规则见 [AGENTS.md](../../AGENTS.md)，项目事实见 [项目上下文](PROJECT_CONTEXT.md)。

## 1. 任务背景

- 任务类型（新功能 / 缺陷修复 / 重构）
- 当前现象或使用场景（缺陷补充最短复现步骤和实际结果）
- 任务来源或相关记录（填写文件路径、Issue 或可核对的证据）

## 2. 任务目标

- 期望的可观察结果（填写一句可验收的描述）
- 需要保留的现有行为（重构时列出关键不变量）

## 3. 相关代码文件

- 入口、调用方和数据边界（填写路径）
- 相关测试、配置和文档（填写路径）

## 4. 功能需求

1. 主流程（填写输入、操作及期望输出）
2. 边界场景（填写空值、错误或并发等适用场景）
3. 行为变化（缺陷写预期结果，重构写需要保持的对外契约）

## 5. 技术约束

- 写明适用的技术栈、兼容性、数据来源和依赖限制。
- 引用项目约定，记录本任务明确授权的例外。

## 6. 允许修改的范围

- 列出可修改及可新增的文件或目录。
- 标注需先确认的扩展范围及其原因。

## 7. 禁止执行的操作

- 遵循 [AGENTS.md](../../AGENTS.md) 的敏感文件和 Git 约束。
- 写明本任务额外禁止的操作，例如是否禁止改动依赖、对外契约或部署配置。

## 8. 验收标准

- [ ] 主流程符合预期。
- [ ] 适用的边界场景和现有行为得到验证。
- [ ] 差异与授权范围一致。

## 9. 测试要求

- 说明需先核对的基线或复现步骤。
- 列出重点用例和需要执行的项目命令。
- 记录实际结果及未执行原因，将环境阻塞和业务失败分别说明。

## 10. 最终报告格式

1. 任务完成情况和可见结果。
2. 修改或新增的文件。
3. 关键实现思路。
4. 技术问题、假设和剩余风险。
5. 实际测试、Lint 和 Build 结果。
6. 未完成事项、需要确认的点和 Git 工作区状态。
